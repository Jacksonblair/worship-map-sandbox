Base map (MapLibre native)

Native MapLibre setFilter-based reduction: minor roads drop first (by class), buildings/park shapes thin out by a stable even subsample. Doesn't touch water at any level.
Different from Detail above -- this widens/restores each layer's own zoom range (setLayerZoomRange) so whichever layers a specific reference zoom would naturally show (e.g. Positron's highway_major_casing/_inner pair, which only naturally activate at zoom 11+) stay visible regardless of the map's real current zoom. Honest limit: this can't conjure geometry that isn't in the loaded tile at the real zoom (vector tiles are server-generalized per zoom) -- it holds a layer's visibility on, it doesn't simulate the reference zoom's actual tile content.

Minimal preset

Exactly 3 categories, nothing else -- water, building, and roads matching OpenFreeMap Positron's own "highway_major_inner" grouping (primary/secondary/tertiary/trunk as one class). Hides every native layer's PAINT (opacity, not visibility) while active, so the map's real source keeps loading tiles for this layer's own data to read -- hiding via visibility instead was the confirmed cause of an earlier "screen goes black" bug (it stops MapLibre from loading tiles at all for a source nothing visible references).

Sprites

Three.js sprites (glowing orb texture, procedural -- no image asset), geo-anchored to St Mary's Cathedral / Sydney Opera House / Queen Victoria Building, bobbing in place. Rendered in its own screen-space scene using map.project() each frame rather than MapLibre's mercator matrix (see spriteLayer.js's header for why), and grows/shrinks with zoom (clamped 0.4x-3x around the zoom they were sized at) so getting closer actually reads as closer. Still costs a full-scene repaint every frame to animate the bob (map.triggerRepaint() has no "just this layer" mode, regardless of what draws the layer) -- watch fps in the stats panel if this feels heavy.
Same hover/bob/zoom-scale mechanic as the orb sprites above (also Three.js, also screen-space), but a Three.Sprite sampling a cropped clone of apps/mobile's dungeonmode icon font (dungeon-mode-mask.png, via texture.offset/.repeat -- no manual UV shader math) instead of a procedural circle -- a cross over St Mary's, an owl-like face over the Opera House, an archway over the QVB. Each has its own pulsing, additively-blended glow sprite behind it, reusing the same shared glow texture the orbs above use. Independent toggle from the orbs above; both can be on at once to compare.

Comedy club names

Web-searched real venues (The Comedy Store, Sydney Comedy Club, Happy Endings) -- coordinates hand-approximated from each venue's published address, same standard as the other seeded places above. Each name is boxed via textBox.js's ┌─┐│└┘ layout engine, rendered with REAL box-drawing glyphs -- dungeon-mode.png (used for letters) turned out to reskin its punctuation-range codepoints into unrelated maze shapes, but the OTHER dungeonmode font variant, dungeon-437.png, has genuine CP437 box-drawing glyphs at those same positions. Border cells sample dungeon-437, letter cells sample dungeon-mode -- both through the same glyphUVRect atlas math, picked per-character by boxLayout.js. Glow is real bloom post-processing (glowEffects.js, Three's EffectComposer/UnrealBloomPass) instead of a background halo sprite -- it thresholds/blurs the box's own actual rendered pixels, so it follows the box's real shape uniformly. A ring of card-suit lights chases clockwise around the box's full perimeter as a separate overlay drawn on top of an always-intact border (marqueeLayout.js), independent in color/glow from the border/text. Every visual knob below is per-place (labelSettings.js's schema, rendered by labelSettingsPanel.js) -- live, no reload needed.
